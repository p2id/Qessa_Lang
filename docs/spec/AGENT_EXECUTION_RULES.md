# قواعد تنفيذ الوكيل (إلزامية)

1. لا ادعاء قراءة ملف أو تنفيذ اختبار لم يحدث فعلًا.
2. لا تُكتب نتائج متوقعة في `VERIFICATION_LOG.md`. كل سطر نتيجة يأتي من أمر نُفذ.
3. إنشاء مواصفة ليس تنفيذ ميزة، ونجاح الاختبارات الحالية ليس اكتمال اللغة.
4. لا يُحذف اختبار فاشل ولا يُضعف لتجاوز بوابة. إن كان الاختبار خاطئًا يُسجل السبب في `DECISIONS.md`.
5. الاختبار الذي لم يُشغَّل أو تُخطي لا يُعد ناجحًا. وتُسجَّل الأدوات غير المتاحة كقيد.
6. لا Mocks كدليل تكامل، ولا Stub أو Placeholder دون إفصاح في `FEATURE_PARITY.md`.
7. لا تغيير بصمت في سلوك اللغة أو ABI. أي تغيير يُحدّث المواصفة والاختبارات والمصفوفة معًا.
8. ممنوع silent fallback: أي عقدة أو رمز غير مدعوم يجب أن ينتج خطأ ترجمة، لا قيمة افتراضية.
9. لا إعادة كتابة شاملة دون تحليل مخاطر وموافقة (D-006).
10. كل تغيير مرتبط بمعرّف متطلب (`QES-*`) واختبار أو مبرر موثق.
11. الأعمال خارج النطاق تُسجل في `TRACEABILITY.md` ولا تُنفذ تلقائيًا.
12. لا يُنتقل بمتطلب إلى `VERIFIED` إلا بدليل منفذ مسجل. ولا تُحسب نسبة إنجاز يدويًا.
13. لا تُعلن عبارة «اكتمل» أو «جاهز للإنتاج» إلا باجتياز كل بوابات `TESTING_AND_ACCEPTANCE.md`.
14. لا تعديل لهذه القواعد دون تسجيل قرار.
15. التغييرات السابقة للمستخدم تُحفظ، ولا يُستبدل تنفيذ قائم قبل فهمه وتسجيل سبب استبداله.
