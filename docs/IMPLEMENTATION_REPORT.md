# تقرير تنفيذ Qessa

## المصدر والنطاق

المصدر: [مشاركة Qessa على chat.z.ai](https://chat.z.ai/s/c7994bb0-03e6-4fcc-9dab-d79c77915d7b). نُقلت شجرة Rust والمترجم الذاتي والمكتبة القياسية والأمثلة إلى `/home/ubuntu/qessa`، ثم فُحصت وشُغلت على Linux x86-64 باستخدام Rust/Cargo المتاحين. حافظ التنفيذ على بنية المشروع بدل استبدالها.

## التغييرات المنفذة

عُدّل `Cargo.lock` ليتوافق مع Cargo المتاح ومع إصدار الحزمة. أُضيف تضمين stdlib تلقائيًا وخيار `--no-stdlib`، وتمرير وسائط البرنامج وإرجاع رمز الخروج الحقيقي في `run`، وأسماء حصرية مع حذف مضمون للملف التنفيذي المؤقت. أضيفت أخطاء للبناء عند وجود دوال أو متغيرات أو syscalls غير معرفة، وتعريفات دوال مكررة، أو غياب `fn main`؛ كما يُرفض الربط برموز خارجية غير مدعومة.

عُدّل parser ليتعامل مع الفواصل المنقوطة ويحلل `new` قبل ذراع identifier العام. وُسعت `read_file` عبر نمو buffer، وعولجت الكتابات الجزئية في `write_file`. أُصلح مثال `test_final.qs` حتى يختبر break بقيمة صحيحة ولا يطبع النجاح إلا عند تحقق الشروط. أضيفت اختبارات تكامل لأوامر CLI والمكتبة القياسية والذاكرة والرموز غير المعرفة وأمثلة المشروع. أُصلح ترتيب ودفع ومحاذاة وسائط stack في Rust وselfhost، وأضيف حفظ معاملات الدوال بعد السادس في prologue الذاتي. كما أُصلح `cg_lookup_local` كي يبحث من الأحدث إلى الأقدم، مطابقًا Rust `HashMap`.

## حالة bootstrap

السبب الجذري المثبت كان اختلاف lookup عند تكرار binding: selfhost `cg_lookup_local` يرجع أول اسم مطابق، بينما Rust backend يستبدل الاسم الأقدم بأحدث offset. `parse_program` يستخدم الاسم `n` أولًا في معالجة top-level let ثم لإنشاء `AST_PROGRAM`; stage-2 كان يستخدم الخانة السابقة بصفر عند `ast_set_c1`، مسببًا الكتابة إلى `0x18`. صار lookup يمر من نهاية جدول locals إلى بدايته، وأضيف نقل معاملات stack الزائدة إلى local slots.

أُضيف harness تكامل ينجز stage-1 → stage-2 → stage-3، يشغل المرحلتين الثانية والثالثة على مصدر فارغ، ويثبت تطابق binary المرحلتين الثانية والثالثة byte-for-byte. ويترجم ويشغل كل compiler مرحلة برنامجًا يختبر 7 و8 معاملات، متوقعًا `7` و`708`. هذا يثبت نجاح bootstrap في نطاق هذه الحالات؛ تبقى الحاجة لاختبار corpus أوسع قبل اعتماد اكتمال المترجم أو جاهزيته للإنتاج.

وسّع harness كذلك اختبار التوافق إلى ثمانية أمثلة selfhost (`arrays`, `factorial`, `full_test`, `hello`, `pointers`, `recursion`, `simple_loop`, `test_final`) عبر stage-1/2/3، مع مقارنة stdout وstderr حرفيًا بمخرجات Rust CLI. كما يثبت أن أمثلة `comprehensive`, `enums`, `modules`, `regions`, و`structs` تُرفض برسالة parse ولا تترك executable. هذه الأمثلة ليست مدعومة بعد في selfhost حتى لو قبلها Rust compiler.

يمرر ELF ذاتي `argc` و`argv` دون وسيطات ومع `alpha` و`beta` في كل مرحلة. كما يقرأ stage-2 وstage-3 مصدرًا يتجاوز 1 MiB، وينتجان executable يعمل؛ هذا يغطي نمو buffer داخل compiler process نفسه.

## مخرجات المشروع

الشيفرة المحدثة موجودة في مجلد المشروع. نتيجة bootstrap ناجحة ضمن النطاق المبيّن، وليست إثباتًا لاكتمال اللغة أو جاهزية الإنتاج.
