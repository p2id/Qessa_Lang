# تقييم فجوات اكتمال ونضج Qessa

**تاريخ التقييم:** 2026-10-15  
**النطاق:** الشجرة الحالية، مرجع اللغة الأصلي، نتائج الاختبارات، وقراءة تنفيذ Rust وselfhost وELF runtime.  
**الغرض:** تحديد ما يمنع وصف Qessa بأنها مكتملة وناضجة وفق الرؤية المعلنة، لا إعطاء نسبة اكتمال تقديرية.

## الخلاصة التنفيذية

Qessa **نموذج أولي فعّال على Linux x86-64**: يترجم مترجم Rust برامج ELF مباشرة، ويمر 13 اختبار تكامل، وقد نجح bootstrap إلى stage-3 في corpus محدد. كما تتطابق نتائج المراحل الثلاث مع Rust في ثمانية أمثلة، وتُختبر `argc/argv`، ومدخل كبير، وحالات رفض.

لكنها **ليست مكتملة أو جاهزة للإنتاج بعد**. هناك تفاوت مهم بين مترجم Rust والمترجم الذاتي، ومزايا من الرؤية لم تُنفذ end-to-end، وعقود لغوية غير محسومة، ومخاطر في تخصيص الذاكرة، واختبارات وتوزيع لا يثبتان بعد الاعتمادية العامة. والأهم أن اختبارًا مباشرًا كشف أن selfhost يقبل اسم syscall غير معروف ويحوّله إلى `syscall_exit` بصمت، بينما يرفضه Rust backend برسالة خطأ.

> الأولوية ليست «زيادة عدد الميزات» قبل إغلاق أخطاء الصحة والسلامة. يجب أولًا ضمان أن كل backend يرفض البرنامج الخطأ بالطريقة نفسها، وألا يكتب allocator خارج حدوده.

## ما تحقق فعلًا

- توليد ELF x86-64 مباشرةً من Rust compiler، من دون assembler أو linker خارجي في مسار البناء الحالي.
- أوامر CLI للبناء والتشغيل، وتمرير `argc/argv` ورمز الخروج، وتضمين stdlib افتراضيًا.
- **13/13** اختبارات تكامل ناجحة، وبناء release ناجح على Linux x86-64.
- bootstrap من stage-1 إلى stage-3، مع تطابق ملفي stage-2 وstage-3 في الاختبار المحدد.
- تشغيل ثمانية أمثلة عبر المراحل الثلاث ومقارنة stdout/stderr مع Rust، واختبار 7 و8 معاملات، و`argc/argv`، وملف مصدر يتجاوز 1 MiB، ورفض حالات malformed وميزات غير مدعومة دون ELF جزئي.
- مترجم Rust يقبل أمثلة المشروع المستقلة الاثني عشر ضمن الاختبارات الحالية.

هذه نتائج جيدة لنموذج أولي؛ لكنها **لا تثبت** صحة كل صياغة اللغة أو كل ABI/ELF أو دعم جميع ميزات الرؤية.

## الفجوات المانعة مرتبة حسب الأولوية

### P0 — سلامة السلوك واتساق المترجمين

#### 1. syscall غير معروف يتحول بصمت إلى خروج العملية في selfhost

- Rust backend يملك **45 اسم syscall** في جدول `syscall_number` ويرفض الاسم غير الموجود.
- المترجم الذاتي لا يملك إلا **7 أسماء**: `read`, `write`, `open`, `close`, `mmap`, `exit`, و`getpid`.
- اختبار مباشر على `syscall_not_real(0)`: Rust رفضه برسالة `unknown syscall`، بينما selfhost أنهى الترجمة بنجاح وأنتج برنامجًا لا يصل إلى التعليمة التالية؛ السبب أن رقم syscall الافتراضي في selfhost هو 60 (`exit`).

**المطلوب:** مشاركة جدول واحد أو توليده للـ backendين؛ رفض الاسم غير المعروف قبل إصدار ELF؛ إضافة differential regression test يمر على كل الاسماء المعروفة ويؤكد رفض الاسم الغريب في Rust وstage-1/2/3. لا يُقبل أي default syscall صامت.

#### 2. حدود allocator ونتائج أخطاء mmap

يحدد ELF runtime المنطقة بحجم 1 MiB ويديرها بـ bump pointer، لكن المسار الفعلي لا يثبت حدًا أعلى قبل زيادة المؤشر. كذلك:

- تخصيص المصفوفة خارج region يطلب mapping بحجم ثابت 1 MiB بغض النظر عن الحجم المطلوب.
- لا توجد حواجز موثقة ومختبرة ضد الحجم السالب، أو overflow في `n * 8 + header`، أو تجاوز سعة region.
- نتيجة `mmap` السالبة لا تتحول بوضوح إلى خطأ لغة آمن قبل استخدامها كمؤشر.
- التخصيص heap العام تراكمي؛ لا توجد آلية تحرير عامة لكل object.

**المطلوب:** checked arithmetic، تحقق من الحجم، فحص نتائج syscalls، نمو/تقسيم mapping عند الحاجة أو رسالة فشل محددة، حدود region، سلوك موحد عند نفاد الذاكرة، واختبارات لا تتجاوز الحدود بصمت. يجب تعريف مصير المؤشرات التي تتجاوز عمر region.

### P1 — مطابقة الرؤية وميزة مقابل semantics

#### 3. selfhost لا يطابق Rust feature-for-feature

الـ selfhost يرفض حاليًا أمثلة `comprehensive`, `enums`, `modules`, `regions`, و`structs` برسائل parse، ولا يصدر ELF. هذه ليست ميزات غائبة عن أمثلة المشروع؛ بل فجوة بين backendين. نجاح stage-3 على subset لا يثبت compiler ذاتي كاملًا.

**المطلوب:** مصفوفة feature parity رسمية، ثم تنفيذ كل ميزة في lexer/parser/AST/sema/codegen/runtime، أو إعلانها خارج الإصدار المستهدف ورفضها بتشخيص مقصود. يجب إعادة بناء selfhost وتشغيل corpus Rust بعد كل دفعة.

#### 4. ميزات يعلنها مرجع اللغة لكنها ليست مكتملة

مرجع اللغة يصف صراحةً هذه الحدود أو الـ placeholders:

- **Generics:** يُحفظ النحو، لكن لا توجد monomorphization أو instantiation مكتملة.
- **Closures:** syntax/AST موجود؛ لا توجد دلالة كاملة للـ capture والبيئة والعمر، والمرجع يذكر أن النتيجة قد تكون `null`.
- **Macros:** لا يوجد expansion كامل.
- **Floats:** قد تحفظ كـ bits داخل `i64`، لكن العمليات الحسابية العشرية ليست مطبقة.
- **Pattern matching:** دعم محدود للأنماط؛ لا يوجد destructuring كامل أو تحقق اكتمال/عدم تداخل موثوق.
- **`use` و`extern`:** سلوك الاستيراد والربط الخارجي ليس عقدًا مكتملًا؛ الربط لرموز خارجية غير syscall غير مدعوم في ELF الحالي.
- **Methods:** التحويل إلى helpers مثل `__method_<name>` لا يعادل بعد نظام methods/dispatch موثقًا ومختبرًا لكل الحالات.

**القرار المطلوب:** إما تنفيذ كل ميزة ضمن الرؤية، أو إصدار مواصفة v1 أصغر وواضحة تسمي غير المدعوم. لا ينبغي إبقاء syntax يوحي بالدعم بينما السلوك يرجع قيمة صامتة أو يتجاهل العنصر.

### P1 — عقد اللغة والذاكرة

#### 5. الدلالات الأساسية غير مثبتة كعقد مستقر

نموذج القيم المقترح يجعل القيم 8-byte `i64`، ويستخدمها للأعداد والمنطق والمؤشرات وenum variants. يلزم تثبيت سلوك:

- overflow وعمليات التحويل والإشارات والقسمة على صفر و`INT64_MIN / -1`.
- shift amounts، مقارنة المؤشرات، وقراءة/كتابة الذاكرة غير المحاذاة.
- حدود المصفوفة، طولها وسعتها، initialized/uninitialized values، وتخطيط struct/enum.
- scope وshadowing وmutability وreturn ضمن الفروع والحلقات.
- تخصيص `new`، عمر الذاكرة، regions المتداخلة، الهروب بمؤشر خارج region، ونفاد المنطقة.
- الفرق بين `null` ومؤشر غير صالح، ومن المسؤول عن التحقق.

كون النوع ديناميكيًا قرار تصميمي مقبول؛ لكن **غياب تعريف سلوكه** ليس كذلك. كل قاعدة تحتاج مواصفة واختبارات عبر backendين.

### P2 — جودة المترجم والاختبارات

#### 6. التغطية الحالية صغيرة قياسًا بحجم اللغة

13 اختبار تكامل جيد كبداية، لكن معظمها يركز على CLI وbootstrap وبعض أمثلة happy path. ما زال ينقص:

- unit/golden tests مفصلة لكل token وprecedence/associativity وقواعد AST.
- differential tests أوسع بين Rust وselfhost، تشمل return values، shadowing والنطاقات، calls متداخلة، closures/features المتقدمة.
- حالات الحدود للفشل: ملف فارغ/كبير، OOM، permissions، كتابة جزئية، syscall errors، integer limits، jump range، stack exhaustion.
- fuzzing للـ lexer/parser ومصادر malformed بحدود زمنية، واختبار ألا يحدث panic أو hang.
- إثبات آلي لصحة ELF headers، entry point، segments، permissions، rodata والقفزات النسبية؛ لا يكفي أن يعمل مثال واحد.
- قياسات compile time/الذاكرة ومراجعة عدم تسريب الموارد في البرامج طويلة العمر.

#### 7. Diagnostics والموثوقية

هناك مسار malformed واحد اختُبر ويعطي `error:`، لكن المطلوب تشخيصات ثابتة مع span صحيح (السطر والعمود وبداية/نهاية الموضع)، لا parse error عام. يجب كذلك إزالة `panic`/`unwrap` من مسارات إدخال المستخدم أو حصرها بثوابت داخلية، وإخراج أخطاء I/O والـ allocator بصيغة واحدة ومفهومة.

### P2/P3 — إصدار قابل للاستخدام والصيانة

- الهدف المثبت Linux x86-64 فقط؛ لا توجد مصفوفة دعم رسمية لـ macOS/ARM أو أي backend آخر. الأفضل تثبيت منصة v1 بدل الادعاء بالتعدد.
- البناء يمر مع **22 تحذير Rust**. يلزم تصنيفها وإزالة غير الضروري وتفعيل بوابة تمنع ظهور تحذيرات جديدة.
- `cargo fmt --check` على المشروع كله ما زال يختلف في ملفات تاريخية؛ فحص الملف المعدل وحده لا يغلق بوابة التنسيق.
- لا توجد بوابة CI مثبتة من checkout نظيف، ولا release checklist رسمية تجمع الاختبارات وELF وbootstrap والـ checksums.
- متطلبات bootstrap للإصدار غير محسومة: هل يحتاج المستخدم Rust لبناء seed، أم يحصل على stage-1 موثوق؟ يلزم توثيق provenance والتحقق من artifact.
- أسماء النسخ في مواد المشروع ليست موحدة تمامًا (مرجع v0.1، compiler يطبع v2.2، وحزمة Rust تحمل إصدارًا مختلفًا). يلزم اعتماد إصدار واحد يميز إصدار اللغة عن إصدار compiler عند الحاجة.

## خطة إغلاق مقترحة وبوابات قبول

### البوابة A — منع السلوك الصامت والمخاطر الحرجة

- إصلاح syscall fallback، وتوحيد جدول 45 syscall في Rust وselfhost.
- إضافة اختبارات متطابقة للـ syscall المعروف وغير المعروف في stage-1/2/3.
- تدقيق allocator: overflow، حدود region، mmap failure، وحجوم array/struct الكبيرة.
- **قبول:** لا اسم غير معروف يُترجم كعملية أخرى، ولا تخصيص يتجاوز حدًا أو يكتب إلى عنوان فشل.

### البوابة B — تحديد v1 ومطابقة backendين

- إنشاء جدول كل ميزة: syntax / parsing / semantics / codegen / runtime / tests.
- اعتماد قرار مكتوب لكل generic/closure/macro/float/match/extern/use/method/region.
- إكمال parity لميزات v1 بين Rust وselfhost، مع corpus تشغيلية.
- **قبول:** كل ميزة معلنة مدعومة end-to-end ومختبرة عبر stage-1/2/3، أو مرفوضة مبكرًا برسالة واضحة إذا كانت خارج النطاق.

### البوابة C — عقد اللغة والصحة

- مرجع رسمي للنحو والدلالات وتخطيط الذاكرة والـ ABI والـ syscalls.
- اختبارات حدود، fuzz smoke، differential testing، ومراجعة ELF آلية.
- **قبول:** لا panic/hang/silent fallback في corpus؛ نتائج Rust/selfhost متطابقة على كل corpus المُعلن.

### البوابة D — إصدار ناضج

- CI من checkout نظيف، بناء reproducible موثق، release artifact/checksum/نسخة موحدة، تعليمات تثبيت وتشغيل، وتصنيف تحذيرات صفر أو استثناءات معللة.
- **قبول:** مستخدم جديد يستطيع إعادة البناء أو التحقق من seed، تشغيل suite كاملة، وفهم حدود اللغة والمنصة دون الاعتماد على سياق تطوير داخلي.

## الحكم النهائي

**Qessa الآن prototype متقدمًا مع bootstrap ناجح ضمن subset، لا مترجمًا مكتملًا وناضجًا.** أكثر ما يعيق ادعاء الاكتمال: سلوك syscall غير معروف الصامت في selfhost، حدود الذاكرة غير الآمنة، فجوة parity بين Rust وselfhost، والميزات الموجودة في الرؤية بلا semantics مكتملة. بعد إغلاق هذه الموانع وتثبيت عقد v1، تصبح بقية الأعمال قابلة للقياس كبوابات إصدار بدل أن تبقى وعودًا عامة.

## تصحيحات وإضافات من تدقيق المصدر (2026-10-18)

- الصمت الخاطئ في المترجم الذاتي أوسع من syscall: معرّف مجهول يُترجم إلى 0، وإسناد/عنوان متغير مجهول يُتجاهل أو يصبح 0، ودالة مجهولة تولّد `ud2` وقت التشغيل.
- مترجم Rust نفسه يعيد 0 بصمت لـ `Match` و`Closure` و`MacroCall` (`codegen/mod.rs:790`).
- `alloc_bytes` في stdlib يفحص `mmap < 0`، لكن `__alloc_array` في مسار region بلا فحص حد، وفي `emit/mod.rs` تعليقات تقر بـ bug في حساب الطول.
- الحزمة 3.0.0 والمترجم الذاتي يطبع v2.2.
