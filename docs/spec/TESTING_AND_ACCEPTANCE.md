# الاختبارات ومعايير القبول (TESTING_AND_ACCEPTANCE)

الأرقام المعلّمة (P) اقتراح قابل للتعديل. لم يُنفذ أي معيار بعد (انظر `VERIFICATION_LOG.md`).

## 1. مستويات الاختبار
Unit لكل مرحلة؛ Golden (رموز، AST، تشخيصات، بايتات حرجة)؛ Integration (CLI، I/O، وسائط، رموز خروج)؛ Differential (Rust مقابل stage-1/2/3: نجاح/رفض، stdout، stderr، exit code)؛ Bootstrap؛ Boundary؛ Fuzz؛ Platform (تشغيل فعلي لكل منصة)؛ Regression canaries.
لكل ميزة: اختبار إيجابي، وسلبي، وحدودي، وdifferential، ولكل منصة معلنة.

## 2. معايير القبول النهائية (AC)
| المعرف | المعيار |
|---|---|
| AC-01 | **صفر silent fallback:** corpus سلبي (معرّف/دالة/syscall مجهولة، match/closure/macro/generic غير منفذة، ميزة غير مدعومة) يُرفض على Rust وstage-1/2/3 بتشخيص متطابق وبلا ملف ناتج |
| AC-02 | صحة الترجمة: corpus إيجابي ≥ 200 برنامج (P) يطابق مخرجات مرجعية مكتوبة يدويًا، لا مولدة من المترجم نفسه |
| AC-03 | فحص كل تخصيص: اختبارات حد (حجم سالب، overflow، امتلاء region، فشل `mmap` بحقن خطأ) |
| AC-04 | تطابق Rust/selfhost على كل corpus المعلن |
| AC-05 | عقد الذاكرة في `MEMORY_AND_ABI.md` §2 مطبق ومختبر |
| AC-06 | Bootstrap: stage-2 = stage-3 بايتًا ببايت من بيئة نظيفة لكل هدف (ISA×حاوية) |
| AC-07 | بناء قابل لإعادة الإنتاج: بناءان مستقلان ينتجان checksums متطابقة |
| AC-08 | تشخيصات بمواضع صحيحة (سطر/عمود/بداية/نهاية) بـ golden لكل نوع خطأ |
| AC-09 | Fuzz لـ lexer/parser: ≥ 10^6 مدخل لكل هدف (P)، بذور محفوظة، صفر panic/hang |
| AC-10 | تحقق بنيوي آلي لكل حاوية (ELF/Mach-O/PE): headers، segments، W^X، entry، حدود rel32 |
| AC-11 | تشغيل فعلي لكل منصة معلنة على مشغّل حقيقي. لا يُعلن دعم منصة بلا ذلك |
| AC-12 | ذرية الإخراج: حقن فشل أثناء الكتابة لا يترك ملفًا جزئيًا |
| AC-13 | صفر تحذيرات rustc، وclippy بـ `-D warnings`، أو استثناءات معللة مكتوبة |
| AC-14 | `cargo fmt --check` نظيف؛ ومنسّق Qessa idempotent |
| AC-15 | تغطية أسطر ≥ 85% للواجهة الأمامية و≥ 90% للشيفرة الحرجة (جدول syscall، التخصيص) (P) |
| AC-16 | أداء: baseline لزمن الترجمة وحجم الناتج وزمن تشغيل corpus؛ لا تراجع > 10% (P) |
| AC-17 | الأدوات: REPL وdebugger وLSP باختبارات بروتوكول؛ linter بقواعد مختبرة؛ مدير الحزم يحل ويقفل بإعادة إنتاج |
| AC-18 | التوثيق: سكربت يفحص أن كل رقم/ادعاء في الوثائق يطابق آخر تشغيل؛ لا ميزة موثقة بلا اختبار |
| AC-19 | التوزيع: artifacts وchecksums وSBOM؛ التثبيت من artifact في بيئة نظيفة |
| AC-20 | سلسلة التوريد: `cargo deny/audit` للتراخيص والثغرات؛ `Cargo.lock` مقفل؛ لا تبعيات غير مبررة |
| AC-21 | Canary لكل إصلاح P0: اختبار يفشل عند إزالة الإصلاح |
| AC-22 | الأنواع الاختيارية: اختبارات قبول ورفض أخطاء الأنواع |
| AC-23 | الذاكرة التلقائية: اختبارات إجهاد طويلة بلا تسرب مقيس ولا use-after-free (بعد اعتماد OQ-2) |
| AC-24 | توافق: سياسة إصدار، وبرامج golden من كل معلم تبقى صالحة |
