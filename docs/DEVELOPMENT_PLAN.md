# خطة تطوير Qessa

**الحالة:** خطة تنفيذية متدرجة، محدثة بعد توسيع corpus bootstrap بتاريخ 2026-10-15.  
**نطاق الإثبات الحالي:** Linux x86-64؛ bootstrap ينجح للمجموعة المحددة أدناه، مع subset ذاتي أضيق من Rust.

## ملخص تنفيذي

المترجم الحالي يبني برامج ELF، وتجتاز 13 اختبارات تكامل تشمل bootstrap تكراريًا إلى stage-3. تشغل كل مرحلة ثمانية أمثلة ضمن subset الذاتي بمخرجات مطابقة لـ Rust، وتُرفض خمسة أمثلة متقدمة برسائل parse دون ELF. أُصلح عيب shadowing، واختُبر ABI لوسائط stack. لا يزال المشروع يحتاج توسيع دلالات اللغة والذاكرة وELF، وإزالة 22 تحذير Rust، وتحسين التنسيق والتوزيع؛ نجاح bootstrap لا يعني اكتمال الميزات أو جاهزية الإنتاج.

**مبدأ الإصدار:** لا يُعلن إصدار مستقر قبل نجاح البوابات المرحلية، ولا يُخفى أي قصور مثبت. تُفصل «يُحلل» عن «يُولد له كود» عن «اختُبر تشغيلًا» في الوثائق.

## الحالة الابتدائية المثبتة

- `cargo test --locked`: 13 اختبار تكامل ناجح.
- `cargo build --release --locked`: ناجح على بيئة Linux x86-64 الحالية.
- أمثلة `hello` و`cat` و`wc` و`test_final` تعمل وفق الاختبارات المرفقة.
- bootstrap: stage-1 → stage-2 → stage-3؛ empty input و7/8 arguments و8 أمثلة ناجحة عبر المراحل، مع تطابق خرج الأمثلة مع Rust وstage-2/3 byte-for-byte. خمس أمثلة متقدمة ترفضها النسخة الذاتية دون إخراج ELF.
- يطبع البناء 22 تحذيرًا غير قاتل. لا توجد حاليًا مصفوفة توافق منصة، اختبار fuzzing، أو بوابة CI موثقة ضمن ما فُحص.

## أولويات التنفيذ

### المرحلة 0 — خط أساس قابل للتكرار (بدأت)

**العمل:** حفظ أوامر إعادة الإنتاج؛ تشغيل الاختبارات على الشجرة نفسها؛ إضافة regression tests للعيوب المؤكدة؛ عدم تغيير semantics إلا مع اختبار.

**المعيار:** كل تعديل يمر عبر `cargo test --locked` و`cargo build --release --locked`، مع smoke tests للحالات المرتبطة به. فحص `cargo fmt --check` حاليًا يُظهر فروقًا تاريخية واسعة في الشجرة؛ لا يُعاد تنسيق كل المشروع ضمن إصلاح موضعي، وتُضاف بوابة التنسيق بعد حملة تنسيق مستقلة أو تُفحص الملفات المعدلة بمعيار موحد. تسجل النتيجة في تقرير التطوير.

### المرحلة 1 — اتفاقية الاستدعاء وموثوقية codegen (منجزة جزئيًا)

**منجز:** وسائط الدوال التي تتجاوز ستة معاملات تُرسل بترتيب ABI الصحيح مع padding للمحاذاة في Rust codegen والمترجم الذاتي؛ واختبارات تشغيل Rust وselfhost تغطي 7 و8 معاملات. أضيف حفظ معاملات stack في prologue الذاتي.

**بعدها:**
- اختبارات لعناوين الدوال و`call_patches`، الدوال المتداخلة/الاستدعاء الذاتي، ترتيب تقييم الوسائط، stack alignment، وقيم `argv`.
- تدقيق read/write للمواقع ذات offsets السالبة والموجبة والإطارات ذات عدد locals كبير.
- رفض أي codegen diagnostic قبل إخراج ملف تنفيذي، وعدم ترك `UD2` غير مفسر في برنامج صالح.

**المعيار:** اختبارات الحدود والتشغيل تعيد القيم المتوقعة، ولا ينتج binary عند خطأ codegen أو sema.

### المرحلة 2 — bootstrap وإعادة البناء (اجتازت بوابة stage-3؛ التوسعة مستمرة)

**ما نُفذ ومعايير القبول المتحققة:**
- **منجز:** أُصلح `cg_lookup_local` ليراجع bindings الأحدث أولًا، مثل `HashMap::insert` في Rust backend. كان `parse_program` يعيد استخدام الاسم `n`؛ البحث من الأقدم كان يقرأ خانة قديمة صفرية بدل مؤشر `AST_PROGRAM`، ما أفسر الانهيار عند `ast_set_c1`.
- أضيف harness تكامل ينشئ Rust stage-1، ويبني stage-2 من المصدر الذاتي، ويشغل stage-2 على ملف فارغ، ثم يبني stage-3 ويشغله. يقارن الملفين stage-2 وstage-3 byte-for-byte.
- يختبر harness برنامجًا فعليًا عبر stage-1 وstage-2 وstage-3: دوال 7 و8 وسائط يجب أن تطبع `7` و`708`؛ الحالة الأولى تختبر padding لمعامل stack فردي.
- الاختبار يسجل stdout/stderr في assertion failures؛ جميع المراحل اجتازت الاختبار الحالي.
- امتدت التغطية إلى `arrays`, `factorial`, `full_test`, `hello`, `pointers`, `recursion`, `simple_loop`, و`test_final`؛ stdout وstderr يطابقان Rust CLI عبر المراحل الثلاث.
- أضيفت حالات رفض آمن لـ `comprehensive`, `enums`, `modules`, `regions`, و`structs`: تتطلب فشلًا مع `error:` وعدم ترك ملف executable.
- اجتازت كل مرحلة تشغيل `argc/argv` بلا وسائط ومع وسيطين؛ وقرأ stage-2 وstage-3 مصدرًا يتجاوز 1 MiB وأنتجا executable صالحًا.
- يرفض stage-2 مصدرًا malformed برسالة `error:` ولا يترك executable؛ يلزم توسيع حالات malformed والتحقق من spans.

**المعيار المحقق جزئيًا:** stage-1/2/3 تعمل على ملف فارغ، و7/8 function arguments و`argc/argv`، وثمانية أمثلة؛ stage-2 وstage-3 متطابقان بايتًا. Stage-2/3 تقرآن مصدرًا كبيرًا؛ malformed sample واحد مرفوض بأمان. **حد ذاتي مثبت:** parser الحالي لا يقبل الأمثلة الخمسة المتقدمة المذكورة. لا يُستنتج من corpus الحالي صحة جميع المدخلات أو استقرار الإنتاج؛ وسّع malformed spans وI/O failures ووسائط أكثر.

### المرحلة 3 — صحة parser والتحليل الدلالي

- إنشاء corpus لاختبارات lexer/parser لكل token وprecedence/associativity وsemicolon/comment/string/escape وحالات EOF والأخطاء.
- اختبار AST golden أو snapshot بمدخلات صغيرة، والتحقق من أرقام الأسطر والأعمدة.
- استكمال فحص أسماء الدوال والمتغيرات والتكرار والنطاقات والـ modules، مع تحديد صريح للميزات unsupported.
- تعريف قواعد `new`, closures, regions, structs/enums, tuples, macros؛ إما تنفيذ end-to-end أو رفضها برسالة دقيقة بدل القبول الشكلي.

**المعيار:** لا panic، لا silent fallback، ورسائل تشخيص مستقرة تتضمن span صحيحًا؛ كل ميزة موثقة لها اختبار قبول.

### المرحلة 4 — الذاكرة وstdlib والـ runtime

- فحص overflow وallocation failure في `alloc_bytes`, buffer/dynarray و`read_file`; التحقق من حد أقصى اختياري للموارد.
- اختبار ملفات فارغة وكبيرة، كتابة جزئية، disk/permission errors، سلاسل طويلة، وقيم signed/unsigned وboundary numbers.
- تحديد lifetime/ownership للذاكرة وقرار واضح بشأن تحريرها؛ حاليًا تخصيص `mmap` تراكمي، فلا يُفترض أن الاستخدامات طويلة العمر آمنة.
- توثيق واجهات syscalls المدعومة وشروط Linux x86-64، وإرجاع أخطاء واضحة من stdlib.

**المعيار:** اختبارات حدودية وعدم كتابة خارج buffer أو إنشاء ملف نجاح زائف عند فشل I/O.

### المرحلة 5 — ELF وواجهات النظام

- اختبار رؤوس ELF وentry point وsegments وpermissions و`.rodata` وrel32 ranges باستخدام `readelf` و`file` وتشغيل فعلي.
- تحقق atomic لإخراج الملف: اكتب إلى مؤقت، `fsync` عند الحاجة، ثم rename؛ لا تترك executable جزئيًا عند الفشل.
- توثيق ABI: SysV x86-64، أول ست وسائط في السجلات، ما يليها في stack، قواعد stack alignment، وsyscall ABI.
- دعم منصات أخرى فقط عبر طبقة backend واختبارات مخصصة؛ لا توسعة ضمنية خارج Linux x86-64.

**المعيار:** binaries قابلة للفحص والتشغيل، وفشل الكتابة/التوليد لا يترك ملفًا مضللًا.

### المرحلة 6 — الجودة، الأمن، والأداء

- إزالة أو تبرير التحذيرات الـ22؛ عدم تعطيل lint بالجملة.
- إضافة fuzzing محدود lexer/parser وملفات malformed مع timeouts، وsanitizing/تحقق من offsets حيث يمكن.
- قياس زمن compile وذاكرة البناء وتشغيل corpus؛ لا تحسين قبل baseline.
- مراجعة حدود الثقة: أسماء/مسارات الملفات، الملفات المؤقتة، symlinks، صلاحيات executable، والمدخل غير الموثوق.

**المعيار:** fuzz smoke متكرر بلا panic/ hang، تحذيرات معروفة ومُعالجة، ومقاييس قابلة للمقارنة.

### المرحلة 7 — التوزيع والوثائق

- إضافة CI Linux x86-64 يبني ويختبر من checkout نظيف، ويرفع artifacts وchecksums.
- تثبيت إصدار وcommit، تعليمات تثبيت وتشغيل، grammar مرجعي، دليل CLI، جدول ميزات مدعومة/جزئية/غير مدعومة، وأمثلة.
- إنشاء release checklist يضم اختبارات Cargo، أمثلة، bootstrap reproducibility، ELF inspection، وchecksums.

**المعيار:** يمكن لمستخدم جديد إعادة البناء من checkout نظيف واتباع وثائق غير معتمدة على ملفات البيئة.

## سجل التنفيذ في هذه الجولة

- إعادة تشغيل خط الأساس: `cargo test --locked` و`cargo build --release --locked` نجحا قبل التعديل.
- **منجز:** إصلاح latest-binding lookup في selfhost، وحفظ معاملات stack الزائدة؛ انكشف السبب باختبار stage-2 وGDB ثم أُثبت بعد الإصلاح.
- **التحقق النهائي لهذه الجولة:** `cargo test --locked` (13/13) و`rustfmt --check tests/cli.rs` نجحا. bootstrap يمر على 7/8 args، و`argc/argv`، ومصدر >1 MiB، وثمانية أمثلة عبر المراحل الثلاث بمخرجات مطابقة لـ Rust، ويرفض خمس أمثلة unsupported ومدخلًا malformed دون ELF.
- **تنسيق الشجرة:** ثبت `rustfmt` وفشل `cargo fmt --check` بسبب 157 موضع فرق تنسيق في عدة ملفات. لم يجرِ تنسيق شامل لئلا يدخل تغييرات واسعة خارج المهمة؛ توثق الحالة إلى أن تُنفذ حملة منسقة منفصلة.
- **الباقي:** argv بأطوال إضافية، وmalformed spans وI/O errors، وأعداد stack arguments الأعلى؛ إضافة دعم end-to-end أو diagnostics أدق للأمثلة المتقدمة؛ وتدقيق ABI والذاكرة والتحذيرات وCI.

## خارج النطاق حتى اجتياز البوابات

لا توصف اللغة بأنها مكتملة الميزات، ولا يُعلن دعم Windows/macOS أو ABI آخر، ولا يُعتمد self-hosting، ولا يُنشر الإصدار على أنه production-ready قبل تحقق المعايير أعلاه.
