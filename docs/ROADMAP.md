# خارطة تطوير Qessa

**آخر تحديث:** 2026-10-14.  
**المنصة المثبتة:** Linux x86-64، ELF.  
**حالة البوابات:** اختبارات CLI والـ bootstrap الحالي ناجحة؛ اكتمال اللغة وجاهزية الإنتاج غير مثبتين.

## المبدأ

تُغلق المراحل باختبارات قابلة لإعادة التنفيذ، لا بمجرد تغيير الشيفرة. يفصل المشروع بين «يُحلل» و«يُترجم» و«اختُبر تشغيلًا». لا يعني نجاح مجموعة bootstrap المحدودة أن جميع ميزات اللغة أو البرامج مدعومة.

## المرحلة 0 — خط الأساس

**الحالة: منجزة ضمن النطاق الحالي.** أُعيد بناء المشروع واختباره من الشجرة، وأضيفت اختبارات CLI وذاكرة وتشغيل أمثلة.

**التحقق الحالي:** `cargo test --locked` ينجح مع 13 اختبارًا تكامليًا؛ `cargo build --release --locked` ينجح. الملف `tests/cli.rs` يمر بفحص rustfmt، بينما لا يزال الفحص الشامل `cargo fmt --check` يظهر فروق تنسيق تاريخية في ملفات أخرى.

## المرحلة 1 — CLI والـ runtime الأساسي

**الحالة: منجزة ضمن النطاق المختبر.** المكتبة القياسية مضمنة افتراضيًا مع `--no-stdlib`، و`run` يمرر الوسائط ورمز الخروج، ويُنظف الملف التنفيذي المؤقت. أضيفت diagnostics للرموز المجهولة والتعريفات المكررة وغياب `main`. عولج نمو `read_file` والكتابات الجزئية في `write_file`.

## المرحلة 2 — اتفاقية استدعاء x86-64

**الحالة: الإصلاحات المؤكدة منجزة، التغطية مستمرة.** عُكس ترتيب دفع وسائط stack الإضافية، وأضيف padding للمحاذاة قبل الاستدعاء. في selfhost تُقرأ معاملات الدالة بعد السادس من stack إلى slots محلية. اختُبرت دوال 7 و8 معاملات عبر Rust compiler، ثم عبر المراحل الذاتية.

**المتبقي:** تغطية 7 و8 وما فوق، أعداد فردية/زوجية من الوسائط، syscall limits، nested calls، recursion، والحالات التي تستهلك locals كثيرة؛ كذلك تثبيت قواعد stack alignment والتحقق منها آليًا.

## المرحلة 3 — إصلاح bootstrap والتحقق من إعادة البناء

**الحالة: اجتازت بوابة stage-3 للحالات المختبرة.** كان السبب الجذري أن `cg_lookup_local` في المترجم الذاتي يبحث من أقدم binding إلى أحدثه، بخلاف Rust backend الذي يستبدل الاسم القديم بآخر تعريف. في `parse_program` يعاد استخدام الاسم `n` داخل فرع top-level let ثم لعقدة البرنامج؛ لذلك كان stage-2 يقرأ خانة صفرية قديمة بدل مؤشر `AST_PROGRAM` وينهار في `ast_set_c1`. عُكس البحث ليطابق Rust backend.

يختبر `self_hosted_compiler_bootstraps_through_stage_three` ما يلي:

1. بناء stage-1 بمترجم Rust.
2. استخدام stage-1 لإنشاء stage-2 من المصدر الذاتي.
3. تشغيل stage-2 على ملف Qessa فارغ.
4. استخدام stage-2 لإنشاء stage-3 وتشغيله على ملف فارغ.
5. مقارنة stage-2 وstage-3 بايتًا ببايت.
6. ترجمة وتشغيل دوال 7 و8 معاملات بكل مرحلة، والتحقق من الناتجين `7` و`708`.
7. ترجمة وتشغيل 8 أمثلة متوافقة بكل مرحلة ومقارنة stdout/stderr مع Rust CLI.
8. التحقق من رفض أمثلة `comprehensive`, `enums`, `modules`, `regions`, و`structs` بتشخيص ودون ELF.
9. اختبار `argc/argv` بلا وسيطات ومع وسيطين في كل مرحلة، وقراءة مصدر أكبر من 1 MiB في stage-2/3.
10. التأكد من رفض مصدر malformed مع diagnostic ودون executable جزئي.

**العمل التالي:** إضافة حالات malformed أكثر والتحقق من spans، و`argv` بأطوال إضافية وI/O errors، وعينات أكثر للـ locals والـ stack arguments؛ وتنفيذ الميزات المتقدمة أو تقديم diagnostics محددة بدل parse errors عامة. أمثلة Rust الناجحة لا تعني دعمها في selfhost.

## المرحلة 4 — دلالات اللغة والتحليل

- بناء corpus lexer/parser يغطي precedence وassociativity والتعليقات والسلاسل والهروب والفواصل ونهاية الملف وأخطاء الصياغة.
- اختبار AST snapshots ومواضع الأسطر والأعمدة.
- تعريف السلوك واختباره للـ scopes وshadowing وclosures وregions وstructs/enums وtuples وmacros و`new`.
- إما دعم الميزة end-to-end، أو رفضها بوضوح؛ لا يُعد وجود AST وحده دعمًا كاملًا.

**معيار الإغلاق:** لا panic أو silent fallback في corpus؛ diagnostics مع spans دقيقة؛ كل ميزة موثقة لها اختبار تشغيل أو رفض مقصود.

## المرحلة 5 — الذاكرة وstdlib وواجهات النظام

- **مانع أولوية عالية:** توحيد syscall table: Rust يملك 45 mapping مقابل 7 في selfhost، وقد ثبت أن selfhost يحول اسمًا مجهولًا إلى syscall 60 (`exit`) بصمت؛ أصلح ذلك قبل اعتماد selfhost.
- اختبار overflow وفشل التخصيص في allocator وbuffers وdynamic arrays.
- اختبار ملفات فارغة وكبيرة، الكتابات الجزئية، أخطاء المسار والصلاحيات، وعمليات I/O.
- فحص حدود region (1 MiB) وحجوم المصفوفات/السجلات الكبيرة ونتائج `mmap` السالبة؛ منع الكتابة خارج المساحة أو استعمال قيمة الخطأ كمؤشر.
- تثبيت سياسة lifetime وتحرير الذاكرة أو تحديد الحدود؛ توثيق تخصيص `mmap` التراكمي.
- توثيق syscalls المدعومة وحدود الوسائط وسلوك قيم الخطأ.

## المرحلة 6 — ELF والجودة والأداء

- تحقق آلي من ELF headers وsegments وpermissions وentry point و`.rodata` وrel32 ranges باستخدام `readelf` و`file` وتشغيل فعلي.
- جعل الإخراج ذريًا وعدم ترك binary جزئي عند فشل البناء.
- تصنيف التحذيرات الـ22 وإزالة غير اللازم منها؛ تجنب إخفاء lint جماعيًا.
- إضافة fuzz smoke محدود لمدخلات lexer/parser مع timeouts، وقياس compile time والذاكرة قبل التحسين.
- مراجعة الملفات المؤقتة والمسارات والصلاحيات والمدخلات غير الموثوقة.

## المرحلة 7 — التوزيع والتوثيق

- CI على Linux x86-64 يبني ويختبر من checkout نظيف؛ يحفظ artifacts وchecksums.
- تحديد إصدار وcommit ثابتين؛ توثيق build/install/CLI والميزات المدعومة والجزئية وغير المدعومة.
- بناء release checklist يشمل الاختبارات والأمثلة والـ bootstrap وELF inspection والـ checksums.
- حسم هل يتطلب التوزيع Rust كأداة seed، أو يوفر stage-1 موثقًا ومتحققًا.

## بوابة الإصدار

لا يعلن المشروع stable أو production-ready قبل نجاح corpus الموسع، والفحص الآلي للـ ELF والـ CLI والذاكرة، ومصفوفة المنصات المعلنة، وحسم التحذيرات ومتطلبات bootstrap، وإعادة بناء موثقة من checkout نظيف. نجاح stage-3 الحالي يغلق مانعًا محددًا فقط ولا يغلق هذه البوابة بالكامل.
