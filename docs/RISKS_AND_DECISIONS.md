# المخاطر والقرارات المفتوحة في Qessa

## المخاطر

| الخطر | الأثر | الحالة/الإجراء |
|---|---|---|
| تغطية bootstrap محدودة | نجاح حالات قليلة لا يثبت صحة compiler على كل البرامج أو الحالات الطرفية | harness يثبت stage-1 → stage-2 → stage-3، empty input، 8 أمثلة متوافقة التشغيل، رفض 5 أمثلة غير مدعومة، دوال 7/8 معاملات، `argc/argv` بلا وسيطات ومع اثنين، مصدرًا >1 MiB، وmalformed واحدًا؛ تبقى الحالات الأوسع وأعداد stack args الأخرى مفتوحة |
| subset selfhost أصغر من Rust | لا يمكن بناء أمثلة `enum/struct/module/region` ذاتيًا رغم قبول Rust لبعضها | `comprehensive`, `enums`, `modules`, `regions`, و`structs` تفشل حاليًا parse في stage-2 مع diagnostic ولا تنتج ELF؛ يلزم تنفيذها end-to-end أو صياغة diagnostics أوضح |
| اختلاف دلالات locals بين الـ backends | قد ينتج عنه سلوك مختلف في التكرار والنطاقات | عولج السبب المثبت في selfhost: `cg_lookup_local` يبحث عكسيًا مثل Rust `HashMap`; أضيف test للـ latest binding. لا تزال سياسة النطاقات بحاجة إلى عقد واختبارات شاملة |
| 22 تحذير Rust | يضعف وضوح البناء ويخفي التحذيرات الجديدة بين العناصر غير المستخدمة | أغلبها AST/machine-code stubs ومسار emitter قديم؛ يلزم تصنيفها وتنظيفها أو تبريرها |
| تخصيص الذاكرة | `mmap` يوفر buffers ولا توجد آلية تحرير عامة في هذه النسخة | قراءة الملفات أصبحت تنمو عند الحاجة، لكن lifetime والحد الأعلى وفشل التخصيص يحتاجان عقدًا واختبارات |
| syscall غير معروف في selfhost | قد ينفذ فعلًا مختلفًا بصمت بدل إيقاف الترجمة | تجربة `syscall_not_real(0)` نجحت في selfhost ثم أنهت البرنامج؛ fallback الداخلي هو syscall 60 (`exit`). Rust يرفض الاسم. يلزم توحيد القوائم ورفضه في كل stages |
| تفاوت syscall والذاكرة بين backendين | البرنامج ذاته قد يتصرف على نحو مختلف بين Rust وselfhost، أو يتجاوز allocator حدوده | Rust يحتوي 45 syscall mapping مقابل 7 في selfhost؛ runtime region ثابت 1 MiB ولا يثبت فحص كل حدود التخصيص ونتائج mmap |

## قرارات مثبتة لهذه الجولة

- المنصة المختبرة: Linux x86-64 فقط، والناتج ELF.
- Rust compiler هو seed لإنتاج stage-1 في harness؛ selfhost stage-1 أنتج stage-2، وstage-2 أنتج stage-3 مطابقًا له بايتًا. قرار متطلبات الأدوات لإصدار مستخدم نهائي ما زال مفتوحًا.
- معيار إعادة البناء المعتمد حاليًا: تطابق stage-2 وstage-3 byte-for-byte على Linux x86-64 مع مصدر البناء نفسه.
- stdlib مضمنة في CLI افتراضيًا، مع `--no-stdlib` لتعطيلها.
- ELF التنفيذي يتطلب `fn main`، والـ CLI يرفضه إن غاب.
- استدعاءات النظام المدعومة يحددها جدول `syscall_number`؛ الرمز غير المعروف يفشل في codegen.
- الربط إلى external symbol غير syscall غير مدعوم في ELF الثابت الحالي.

## قرارات لازمة قبل ادعاء الاكتمال

1. توسيع معيار إعادة البناء من fixture محدود إلى corpus ومخرجات برامج متعددة.
2. تحديد هل يُشترط Rust كأداة seed في التوزيع أم تُوزع stage-1 binary موقعة/متحققة.
3. تحديد نسخة Qessa المرجعية وربطها بـ commit أو hash للأرشيف.
4. توثيق حدود اللغة: الأنواع، النطاق، أسبقية العمليات، مؤشرات الذاكرة، overflow، والقسمة على صفر.
5. اختيار سياسة لإدارة الذاكرة وتحويل أخطاء `mmap` وI/O إلى نتائج موحدة.
6. تحديد ما إذا كانت `new` وميزات AST غير المختبرة ضمن النطاق المدعوم.
