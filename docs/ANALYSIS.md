# التحليل الفني لمشروع Qessa

## الخلاصة التنفيذية

تحتوي الشجرة المفحوصة على مترجم Rust يولد ELF x86-64، ومترجم ذاتي بلغة Qessa، ومكتبة قياسية وأمثلة. ينجح بناء Rust والاختبارات، واجتاز bootstrap من stage-1 إلى stage-3 في الحالات المختبرة. عبرت المراحل الثلاث ثمانية أمثلة متوافقة مع subset الذاتي بمخرجات مطابقة لمترجم Rust. في المقابل، ما زالت أمثلة `comprehensive` و`enums` و`modules` و`regions` و`structs` خارج subset parser الذاتي الحالي؛ لذا لا يعني نجاح bootstrap اكتمال self-hosting أو اكتمال اللغة.

## البنية ومسار التنفيذ

يقسم مترجم Rust العمل إلى lexer وparser والتحليل الدلالي وcodegen x86-64 ثم emitter لإخراج ELF. يوفر CLI أوامر `compile` و`run` و`tokens` و`ast` و`asm`. تُضمّن `src/qessac/stdlib.qs` افتراضيًا في أوامر البناء والتنفيذ؛ ويمكن تجاوزها بـ `--no-stdlib`. رمز تشغيل ELF يمرر `argc` و`argv` إلى `main`، ويعيد `run` رمز الخروج الفعلي للبرنامج.

المكتبة القياسية توفر دوال السلاسل والذاكرة والملفات والمصفوفات الديناميكية. عُدّل `read_file` ليوسع الذاكرة بدل الكتابة بعد حد ثابت، وعُدّل `write_file` لمعالجة الكتابات الجزئية. يظل تخصيص الذاكرة المعتمد على `mmap` بلا استرجاع للذاكرة في هذه النسخة.

## ما تم التحقق منه

- `cargo test --locked`: 13 اختبار تكامل ناجح، تشمل `argv`، ورمز الخروج، وإصدار executable وتشغيله، وأخطاء الرموز، وتعطيل stdlib، ومدخلًا أكبر من 1 MiB، وABI لوسائط الدوال، وshadowing، وbootstrap stage-1/2/3.
- أضيف اختبار تكامل لسبعة وثمانية معاملات. أصلح Rust codegen والمترجم الذاتي دفع وسائط stack بترتيب ABI العكسي، مع padding عند عدد فردي لمحاذاة call site؛ الاختبار التشغيلي يمر.
- bootstrap stage-1 → stage-2 → stage-3 ناجح في harness التكامل؛ تطابق ناتجا stage-2 وstage-3 byte-for-byte، وشغلت المراحل الثلاث دوال 7 و8 معاملات بالقيمتين `7` و`708`.
- شغّل كل من stage-1/2/3 أمثلة `arrays`, `factorial`, `full_test`, `hello`, `pointers`, `recursion`, `simple_loop`, و`test_final`، وطابقت stdout وstderr تمامًا مع Rust CLI؛ اختُبرت أيضًا أمثلة `comprehensive`, `enums`, `modules`, `regions`, و`structs` كحالات رفض مع تشخيص ومن دون ELF جزئي.
- عبرت `argc/argv` بلا arguments ومع وسيطين في كل stage؛ وقرأ stage-2 وstage-3 مصدرًا أكبر من 1 MiB ثم أنتجا برنامجًا صالحًا للتشغيل.
- السبب الجذري السابق كان `cg_lookup_local` يبحث من أول local، فيختار تعريف `n` القديم في `parse_program` بدل آخر binding، بخلاف Rust `HashMap`. عكس ترتيب البحث أصلح مؤشر AST، وأضيف تحميل معاملات stack الزائدة في selfhost prologue.
- `cargo build --release --locked`: ينجح على بيئة Linux x86-64 الحالية.
- أمثلة `cat.qs` و`wc.qs` تعمل مع مسار ملف، و`test_final.qs` يجتاز شروطه ويطبع `=== All Passed ===` بعد إصلاح شرط break.
- استدعاءات الدوال والمتغيرات والـ syscalls غير المعرفة تُرفض برسائل خطأ بدل إنتاج ELF سيئ بصمت.

## السبب الجذري وإصلاح bootstrap

كان `cg_lookup_local` في selfhost يمر على bindings من الأقدم إلى الأحدث. في `parse_program` يعاد استخدام الاسم `n` عند معالجة top-level let ثم عند إنشاء عقدة البرنامج، فأعاد lookup الخانة الأولى القديمة ذات القيمة صفرية. أدى ذلك إلى `ast_set_c1(0, funcs)` والكتابة عند `0x18`. عُكس البحث ليطابق Rust backend، الذي يخزن الاسم في `HashMap` ويحل إلى أحدث offset. كما أضيف تحميل معاملات stack بعد السادس إلى prologue الذاتي.

نجح harness جديد في بناء stage-1 من Rust، ثم stage-2 وstage-3 ذاتيًا؛ اجتاز stage-2 وstage-3 ملفًا فارغًا، وتطابق executable المرحلتين بايتًا ببايت. كما ترجمت المراحل الثلاث وشغلت دالتين بسبعة وثمانية معاملات وأنتجت `7` و`708`. يثبت ذلك هذه المسارات فقط؛ يلزم corpus أوسع قبل ادعاء صحة عامة.

## جودة البناء وحدود النطاق

يبني Cargo المشروع مع 22 تحذيرًا غير قاتل، معظمها عناصر AST وتعليمات machine code أو مسارات emitter غير مستخدمة حاليًا. لم تُعالج كلها لأن بعضها يمثل بنية مستقبلية وبعضها في مسارات قديمة؛ ينبغي تقليصها أو توثيقها قبل إصدار مستقر. يقتصر الهدف المثبت على Linux x86-64، ولا يوجد في هذه الجولة إثبات لدعم منصات أخرى أو link لرموز C خارجية.

## الأولويات الفنية المتبقية

1. توسيع bootstrap harness إلى مدخلات malformed و`argv` وملفات كبيرة ووسائط stack بأطوال متنوعة؛ مجموعة الأمثلة الحالية تثبت subset المختبر وتوثق الخمس غير المدعومة.
2. توثيق semantics للـ scopes وshadowing والميزات الموجودة في AST لكنها غير مفعلة end-to-end.
3. إضافة اختبارات حدودية للذاكرة والقفزات وI/O وELF headers والرموز النسبية.
4. تقليل التحذيرات الـ22 وتثبيت فحص تنسيق للمشروع كاملًا بعد حملة تنسيق مستقلة.
5. إضافة CI قابل لإعادة البناء من checkout نظيف ومصفوفة منصة معلنة.
