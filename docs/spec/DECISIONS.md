# سجل القرارات (DECISIONS)

المصدر: إجابات المستخدم بتاريخ 2026-10-18. الحالة `USER` = قرار المستخدم، `ENG` = قرار هندسي مقترح ينتظر تأكيدًا.

| المعرف | القرار | المصدر | ملاحظات وأثر |
|---|---|---|---|
| D-001 | الهدف: لغة **هجينة**، أساسها عام (Core)، وتُشتق منها بقية الحالات (profiles) بتبديل يدوي من المبرمج أو تحويل تلقائي ذكي | USER | توصيتي كانت E (v1 صغير ثم توسع). اختار المستخدم النطاق الأوسع؛ الخطر: اتساع النطاق يرفع احتمال عيوب في الأساس. يعالجه D-006 وبوابات الاختبار |
| D-002 | المترجم الذاتي: يبني نفسه كاملًا مع أدلة إعادة إنتاج (خيار C) | USER | لا يشترط وحده تطابق الميزات بين المترجمين، لكن معيار القبول AC-04 (تطابق Rust/selfhost) أُضيف بموافقة المستخدم على «الأكثر اكتمالًا» |
| D-003 | المنصات: Linux x86-64 (قائمة) + **Linux ARM64 + macOS + Windows** قبل الإصدار | USER | يتطلب backend لكل منصة وحاوية تنفيذية مختلفة (ELF/Mach-O/PE). تحذير: لا يمكن إثبات أي منها دون مشغّلات حقيقية (انظر OQ-1، OQ-4) |
| D-004 | الأنواع: تدريجية. ديناميكي افتراضيًا + أنواع اختيارية يتحقق منها المترجم | USER | يتطلب تمثيلًا نوعيًا في AST وsema، ولا يكفي `i64` الموحد |
| D-005 | الذاكرة: **تلقائية ذكية افتراضيًا + تحكم كامل حر للمبرمج** | USER | الآلية غير محددة بعد (OQ-2). لن يُنفذ شيء قبل موافقة المستخدم على التصميم في `MEMORY_AND_ABI.md` |
| D-006 | سياسة المعمارية: إعادة تصميم **موضعية** للمكونات التي يثبت التدقيق فشلها (خيار B) | USER | المكونات المثبتة: جدول syscall، sema في selfhost، runtime التخصيص، تجاهل Match/Closure/Macro في codegen، غياب فصل ISA/Container |
| D-007 | لا إصدار قبل تنفيذ **كل ميزات الرؤية** (خيار A) | USER | مقترح هندسي (ENG، بانتظار تأكيد): معالم داخلية M0 إلى M7 غير معلنة كإصدارات، لكل منها بوابة اختبار، ليبقى التقدم قابلًا للقياس |
| D-008 | أدوات المطور المطلوبة قبل الإصدار: مواضع أخطاء، Formatter، Linter، REPL، Debugger، LSP، دعم محرر، مدير حزم | USER | أكبر بند كلفة بعد backends. تُنفذ بعد تثبيت عقد اللغة |
| D-009 | التوزيع: Binary جاهز لكل منصة **و**بناء من المصدر، مع بناء قابل لإعادة الإنتاج | USER | يتطلب checksums وسلسلة توريد وبيئات بناء موثقة |
| D-010 | معايير القبول: الأكثر اكتمالًا، وللوكيل إضافة ما يناسب | USER | أُضيفت AC-01 إلى AC-24 في `TESTING_AND_ACCEPTANCE.md` |
| D-011 | نطاق v1 = كل ميزات «الرؤية» المعلنة في وثائق المشروع | USER (مستنتج من D-007) | تُعد الميزة في الرؤية إذا ذكرتها الوثائق: generics وclosures وmacros وfloats وmatch وuse وextern وmethods وregions وstructs وenums وtuples. المرجع الأصلي للغة غير موجود في الأرشيف (OQ-3) |

## أسئلة مفتوحة (تمنع تنفيذ بنود مرتبطة بها)

| المعرف | السؤال | يمنع |
|---|---|---|
| OQ-1 | معمارية macOS (x86-64 أم ARM64 أم الاثنتان) ومعمارية Windows (x86-64 أم ARM64)؟ | تصميم backend لهما |
| OQ-2 | آلية الذاكرة التلقائية: تتبع مراجع، أم استدلال regions/ملكية، أم جامع مخلفات، أم مزيج؟ | أي تنفيذ لـ D-005 |
| OQ-3 | المرجع الأصلي للغة (v0.1 المذكور في الوثائق) غير موجود في الأرشيف. هل يمكن تزويدي به؟ | تثبيت دلالات الميزات «الرؤية» |
| OQ-4 | بيئة تحتوي Rust/Cargo، ومشغّلات Linux ARM64 وmacOS وWindows للاختبار؟ | أي تحقق (`VERIFIED`) |
| OQ-5 | هل أُهيّئ Git للمستودع وأبدأ تتبع التغييرات؟ | تحديد commit في سجل التحقق |
| OQ-6 | صياغة التبديل بين أوضاع الذاكرة والأنواع (سمات `#[...]` على الدوال والوحدات؟ كلمات مفتاحية؟) | تصميم نحو اللغة |

## بدائل رُفضت أو لم تُختر

- A (لغة صغيرة مستقرة): لم تُختر لأن المستخدم يريد نطاقًا أوسع. تبقى معيارًا لبوابة M3 (الأساس).
- نظام أنواع ثابت صارم: لم يُختر (D-004).
- جامع مخلفات كامل كخيار وحيد: لم يُختر (D-005)، لكنه قد يكون أحد مكونات التصميم المقترح.
